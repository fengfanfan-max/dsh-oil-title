# 发布与安装

## 发布到 npm

当前 npm 包名 `dsh-oil-title` 未被占用。

```sh
npm login                       # 一次性
npm test                        # 先跑测试
npm publish --access public     # 发布 0.1.x
```

发布后可以用短名字安装：

```sh
dsh plugin --profile desktop add dsh-oil-title
```

## 打 GitHub Release

```sh
git tag v0.1.0
git push origin v0.1.0
```

仓库内的 `.github/workflows/release.yml` 会在 tag 推送时发布 npm（需要先在仓库 Secrets 里配置 `NPM_TOKEN`）。

## 从 GitHub 安装（无需发布）

```sh
dsh plugin --profile desktop add github:fengfanfan-max/dsh-oil-title
```

DSH 0.2.x 会读取包内的 `peerDependencies` 做安装期版本门禁；本包声明的范围是 `>=0.1.2-rc.1 <0.3.0`，覆盖 0.1.2-rc.1 与 0.2.1-rc.2。

## 升级 dsh 之后

1. 拉取新版本 `@deepseek-ai/dsh-session`、`@deepseek-ai/dsh-session-title`、`@deepseek-ai/dsh-llm` 的 `lib/types/*.d.ts`，确认 README 里列出的 6 个接口仍然存在。
2. `npm test`（`test/compat.test.mjs` 会校验范围）。
3. 新开会话发一条需求，确认侧边栏标题更新且对话中没有多出命名消息。
4. 确认无误后再把 `<0.3.0` 上界按实际验证结果调整。
